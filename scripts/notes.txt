## Answers to your questions

### 1. What is `num_modes`?
`num_modes` is the number of task variations/modes per environment:
- Atari SpaceInvaders: 10 modes (0-9)
- Atari Freeway: 8 modes (0-7)
- Meta-World: 20 modes (0-19) for most algorithms, 10 modes (0-9) for "simple"

Each mode is a different task variation that the agent learns sequentially in continual learning.

### 2. Why not use job arrays?
Job arrays run tasks in parallel. In continual RL, tasks must run sequentially because:
- Each task depends on the previous task's trained model
- The script loads previous models via `--prev-units`
- Parallel execution would break this dependency chain

### 3. Total tasks in the original script
- Atari: 2 environments × 5 algorithms × (10+8 modes average) ≈ 180 sequential task runs
- Meta-World: 6 algorithms × 20 modes = 120 sequential task runs
- Total: ~300 sequential task runs (very long runtime)

## New simple scripts

Two scripts that run one algorithm, one seed, sequentially:

### `run_atari_single.sh`
```bash
# Usage:
sbatch run_atari_single.sh <algorithm> <env> <seed>

# Examples:
sbatch run_atari_single.sh componet ALE/SpaceInvaders-v5 42
sbatch run_atari_single.sh finetune ALE/Freeway-v5 123
```

### `run_metaworld_single.sh`
```bash
# Usage:
sbatch run_metaworld_single.sh <algorithm> <seed>

# Examples:
sbatch run_metaworld_single.sh componet 42
sbatch run_metaworld_single.sh simple 123
```

These scripts:
- Run one algorithm with one seed
- Execute tasks sequentially (as required for continual learning)
- Use default CLI options from the paper
- Do not modify `run_experiments.py`
- Are easier to manage and debug
